# 数据与一致性设计

## Day 1 实际表

| 表 | 作用 |
|---|---|
| metadata | schema_version |
| locations | 虚构校园、实训楼二层、图书馆、学生公寓 |
| devices | 设备主数据，关联位置 |
| incidents | 演示事件及触发时间、状态、规则风险级别 |
| observations | 设备、事件、监测类型、数值、单位、质量、采样时间 |
| knowledge_documents | 演示资料原文、版本与标签 |
| resources | 模拟人员角色及设备资源 |
| conversations / messages | 会话、用户指令、可展示的核查摘要 |
| agent_runs | 运行阶段、状态、取消标记、结果及证据快照 |
| run_events | 每次运行的有序阶段和真实工具结果 |

主键使用独立 ID，外键启用。observations 通过 incident_id 隔离每轮演示；不在前端为不同页面另造数值。设备状态根据所选事件每类最新记录派生，缺失或无效质量不会默认为正常。

run_events 的 `(run_id, sequence)` 唯一。同一会话最多存在一项 queued/running 核查。规则结果与完成摘要在事务中保存，取消后不能覆盖为完成。报告前置的初评结果作为运行快照保留。

每次数据库连接显式关闭，采用默认回滚日志。本期单进程、单机演示，不作为分布式或多租户系统。

## 后续表与约束

方案与审批记录需要绑定精确版本。派发任务需要对“方案版本＋执行项”建立唯一约束，防止重复批准或重试产生重复任务。正式报告保存生成时的监测、方案与任务快照，不能随最新设备状态回写历史事实。
