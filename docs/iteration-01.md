## A：已完成任务的补充记录

暂定负责人：`heqiucan`；互审人：`houda-codes`。建议分支：`codex/task-follow-up-notes`。

**用户可见结果：** 在任务详情的完成报告下输入“补充记录（演示）”，保存后看到文本和服务端时间；刷新、重新打开或服务重启后仍可读取。记录仅作为后续沟通材料，页面继续提示待人工复核。

输入：一个已完成执行任务的真实内部 `task_id`（不是显示编号 TASK-008）、非空补充文本和客户端请求 ID。输出：关联此任务的追加记录及有序列表。来源事件/核查/报告沿用任务关联，不让客户端另填，避免记录串到其他事件。

### 契约草案

| 接口 | 请求/响应 | 边界 |
|---|---|---|
| `GET /api/v1/execution-tasks/{task_id}/notes` | 返回数组；每项为 `id, task_id, content, client_request_id, created_at` | 按服务端 `created_at` 升序、相同时按 `id` 排序；存在但无记录返回 `[]`，未知任务 404 |
| `POST /api/v1/execution-tasks/{task_id}/notes` | 请求 `{content, client_request_id}`；返回保存后的同一记录 | 建议文本去首尾空白后 1–1000 字符；请求 ID 为 UUID；拒绝额外字段、空白和超长值，422 |
| 同一 POST 的重试 | 同 task + request ID + 相同规范化文本返回已有记录 | 首次 201，重复 200；同 ID 不同文本 409；需数据库唯一约束与事务，不能只依赖按钮禁用 |
| 写入条件 | 任务存在且为 `completed` | 未完成/取消/失败任务 409；未知任务 404；不自动把任务推进为完成 |

建议 `execution_task_notes` 独立表，外键关联 `execution_tasks.id`，唯一键 `(task_id, client_request_id)`；ID 与 UTC 时间由服务器生成。只提供追加与读取，不提供编辑/删除接口。通过独立表的约束保持追加语义，不删除或放松既有不可变触发器。

任务存在性与写入条件直接核对数据库中已持久化的状态，不复用会触发模拟进度推进的 `execution.get/_sync` 路径。notes 的读取或写入不能使该任务或其他任务自动完成；状态推进继续由既有执行查询负责。

当前没有登录体系，本轮不增加姓名字段或伪造“已认证操作人”。页面明确为演示补充记录；任何有 API 访问能力的人都可能提交，不能把它用作正式审批或可归责审计。若后续需要真实复核人，应独立设计身份和权限。

记录写入不改 `execution_tasks.payload`、执行日志、已保存执行报告、研判报告、证据快照及事件状态；保留 `verification_status=requires_human_review`。重试任务使用新的 `task_id`，记录不自动继承。UI 保存失败保留输入；网络结果不确定时用同一请求 ID 重试，成功后下一条记录才生成新 ID；改写文本则视为新请求。请求捕获提交时的 `task_id`，切换任务前已发出的请求仍只归属原任务；切换后旧响应不能污染新面板，新提交不能沿用旧任务 ID。不以切换面板或取消浏览器请求承诺撤销已经发出的写入。

## B：知识类别与关键词联合检索

暂定负责人：`houda-codes`；互审人：`heqiucan`。建议分支：`codex/knowledge-category-search`。

**用户可见结果：** 知识页提供“全部类别”和实际资料类别选项，输入关键词后显示交集结果；带首尾空格的同一关键词得到一致结果，无匹配可清空恢复，原文及版本仍可读。

输入：可选关键词、可选类别；资料来自现有 `knowledge_documents`。输出：匹配资料列表、稳定的完整类别选项及资料详情。沿用目前三份预置演示资料，不上传文件、不自动生成预案、不把资料当成正式处置依据。

### 契约草案

| 接口 | 行为 | 兼容性 |
|---|---|---|
| `GET /api/v1/knowledge/search?q=…&category=…` | 继续返回现有 `KnowledgeDocument[]`；q 限长 200，先 strip/casefold，再在标题、正文、标签中做字面子串匹配；类别与关键词按 AND 组合 | 缺省/空白 category 表示全部；类别去首尾空白后精确匹配，建议限长 100；未知类别返回 `[]`；参数超长 422；不改成分页包装 |
| 新 `GET /api/v1/knowledge/categories` | 全部资料中的非空类别，去重后按字符串稳定排序，返回 `string[]` | 不随当前搜索结果缩减；静态路径应在 `/knowledge/{document_id}` 前注册，避免被当成文档 ID |
| 既有 `GET /api/v1/knowledge/{document_id}` | 资料详情、版本和 `is_demo` 保持原字段；未知 ID 404 | 不改已有 ID、正文或版本 |

将知识页请求、loading、error、关键词、类别和选中文档放到局部组件。移除 `App.vue` 中重复的本地知识过滤，避免前后端各套逻辑；初始资料拉取也移到该组件，避免知识请求失败拖累无关页面初始化。类别列表独立加载，搜索和刷新复用同一契约。输入快速变化时，以请求代次或取消机制丢弃旧响应；失败可重试，不能把上一次结果标成当前查询的成功结果。

关键词或类别变化时关闭旧原文选择，避免详情与结果不一致；“清空筛选”同时清空两者。保留原文、版本、演示标识、匹配数量和无结果提示；不扩展新路由框架，不重构其他页面。
