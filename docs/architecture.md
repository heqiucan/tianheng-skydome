# 架构与阶段边界

## Day 1

浏览器通过 Vite 的 /api 代理调用 FastAPI。服务器从 SQLite 读取固定演示数据，运行三项白名单查询工具，保存真实过程事件和规则初评。浏览器通过 SSE 订阅已经落库的记录；完成后关闭连接，刷新后从数据库恢复状态。

所有时间按 UTC 保存，页面转换本地时间。设备状态从所选事件的观测记录派生，历史运行的证据与结果保留快照。缺失证据必须明确显示，不能默认正常。

服务单进程运行；意外重启后尚未结束的任务标为 interrupted，不声称无缝恢复。单独取消接口阻止后续步骤，关闭浏览器不取消任务。数据库连接显式关闭，模型网络请求不能占用写事务。

模型探针与页面规则演示分离。探针只验证服务可访问、模型返回合法工具调用、真实函数执行，以及模型收到函数结果后返回正确事实。未接入正式工作流前，UI 不显示“模型已完成规划”。

## 后续阶段

1. 增加预案和资源查询、风险报告工具，接入模型意图识别和工具选择；校验未知位置、工具、参数、证据引用。
2. 实现方案版本及审批；后端校验明确获批版本后，事务内创建模拟任务。唯一约束防止重复派发。
3. 生成包含证据快照、方案和任务实际状态的事件报告。未完成任务只能输出阶段报告。

## 本机数据与边界

代码位于现有 OneDrive 项目目录。启动脚本将运行数据库与日志置于 LOCALAPPDATA/TianqiongDemo。数据库文件不进入 Git，不直接同步运行中的 SQLite 文件。应用只监听 127.0.0.1；公网部署、认证、多用户权限不是当前交付能力。

校园与设备都是模拟对象。演示规则不是消防标准，不能承担真实火情判断、自动控制设备或人员调度。
